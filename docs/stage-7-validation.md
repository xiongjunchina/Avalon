## HTTPS五人演练

执行 `npm run deploy:rehearse -- verify recovery`，源为本机8445端口、恢复目标8444端口。两者数据库及CA卷各自独立。七组检查全部通过：

1. 编译网页与静态脚本可以访问；CSP等响应头存在；不存在的API返回404，不能被SPA回退页面吞掉。
2. 五个独立Cookie／WebSocket同步；HttpOnly／SameSite／Secure正确，跨源与缺少CSRF标识被拒；关闭加入阻止新用户，原成员仍能加入；重复命令无额外状态变更。
3. 完成一局五次流局判红胜，统计计一局；五轮匿名复盘、收藏、个人资料及设置预设均可读取。
4. 第二局进入表决、只提交第一票后重启容器：原身份、已确认角色、设置、票数恢复，重放该票仍为一票。
5. 停止源应用后备份并还原到空库；十张表的全部行按稳定顺序散列逐一比较相同。损坏文件、恢复到源项目和再次覆盖非空目标均被拒。
6. 持有原凭证的测试客户端在恢复实例认证成功；座位、准备、设置、关闭加入状态、角色、统计、历史、收藏和预设相同。原命令回执仍幂等，其余四人表决后顺利进入任务阶段。
7. 逐次伪造不同X-Forwarded-For仍触发同一来源限流，不能通过请求头取得新的限流额度。
