# 心仪角色加权发牌

适用于本次改版后的新对局。房主仍使用现有“心仪选角”设置，不新增开关。角色数量、阵营比例、法宝和个人视野规则保持原规则。

## 志愿与重复权重

- 开启心仪选角后，第一、第二、第三志愿、其他角色的基础相对权重分别为 **8 / 4 / 2 / 1**。未设置偏好时，所有角色使用基础权重 1。
- 权重不是命中概率，也不表示按玩家顺序抢角色。系统在满足本局角色库存及保护条件的完整分配中随机抽取；志愿只提高相对机会，不保证第一志愿或前三志愿命中。
- 历史读取最近 5 次发牌，按新到旧排列；发牌后中止的对局也计入，避免通过连续重开绕过防连抽。
- 对同一角色的近期连续重复使用降权：未连续重复、连续 1 次、2 次、3 次、4 次及以上，对应整数因子 **81 / 27 / 9 / 3 / 1**。最终相对权重为基础权重乘该因子。统一乘以 81 用于精确整数计算，不影响相对机会。
- 算法用完整可行分配的权重总和进行抽样；总权重和随机票使用 bigint，保存及接口传输时转为十进制字符串，避免精度丢失。

## 保护与审计

原有保护条件仍参与发牌。只有当前角色库存无法满足全部约束时，依次放宽特殊角色冷却、蓝方保护、视野角色保护；审计退让级别分别为 0（全部保护）、1、2、3。玩家页面只说明存在保护与重复降权，不公开其他人的志愿、历史或保护条件。

每局保存算法版本、权重版本、玩家抽样顺序、角色区间顺序、个人志愿、最近角色、实际整数权重、触发的保护条件、最终角色及随机抽样总权重/票值。新局必须以数组保存 `roleOrder`，不依赖 JSON 对象键顺序，避免数据库 JSONB 重排键后无法还原抽样区间；旧审计缺少该字段时保持可读。保存的是开局快照，后续更改个人偏好或算法不会改写旧局依据。管理员界面以原始十进制字符串展示随机票值及区间总权重，长数字可换行，不转换为浮点数或科学计数法。

仅管理员可在**已结束对局**复盘的默认收起区域“发牌依据”查看。普通玩家复盘及进行中的对局响应不包含该审计数据；旧对局没有审计时不展示空白区块。

## 验证关注点

必须检查每种人数的角色库存守恒、随机票边界、偏好和降权对相对机会的影响、保护冲突退让、跨局历史/中止局计入、管理员与普通玩家数据隔离。UI 延续现有心仪选角布局和后台紧凑字体。
