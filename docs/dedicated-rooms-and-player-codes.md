# 专属房与仙友码管理

## 创建、使用专属房

1. 管理员进入网页 `/admin`，打开“专属房与靓号”。
2. 点击“新建专属房”，填写固定六位房号、房间名称、房主管理者的仙友码、默认玩法和可选密码。
3. 房主管理者点击首页“开常规房”，在“开桌方式”选择自己的专属房，确认设置后开桌。
4. 朋友通过房号加入时，有密码才需要输入；通过有效邀请链接加入可直接入房。无需预先登记玩家或审批。

固定房号和配置长期保留；每次开桌有独立房间 ID 和对局记录。同一专属房不能同时开两桌。等待区的当前房主可修改/关闭密码；进入正式开局倒计时后锁定。改密会更新专属房保存的密码并使旧邀请链接失效，已入座玩家不受影响，房主需重新分享邀请链接。房间关闭后，管理员可编辑专属房的默认配置和管理者。

普通房也支持相同的可选密码。新设或修改密码为 4–8 位字符；已有较长密码仍可用于入房，修改时使用新长度限制。随机房号不会使用后台预留的专属房号。

网页和微信小游戏均可选择自己的专属房、设置入房密码，并使用邀请凭证入房。专属房和靓号的后台管理在网页 `/admin` 操作。

## 预留、分配仙友码

- 在“专属房与靓号”预留号码后，系统随机注册不会分配这些号码。列表区分待分配、已分配和历史旧号，已分配号码显示当前持有玩家、原号、分配时间及预留备注。
- “分配记录”保留全部改号历史，可继续加载更早记录。旧版本已保存的分配审计也会展示；旧版分配时未保存的预留备注无法补回。顶部“刷新数据”可重新读取列表和历史。
- 在“仙友用户”找到玩家，点击“改仙友码”，输入新号码；界面先显示是否可用、是否已被占用，保存时数据库再次校验。
- 占用号码不能覆盖；并发分配只允许一个请求成功。
- 修改只改变公开仙友码，账号内部 ID、好友、会员、预设和历史对局归属保持不变。
- 从未开局的账号：旧号立即释放，可重新分配。存在任何已开局记录（含发牌倒计时、未完成或中止对局）：旧号保留，不分配给其他账号；可以恢复给原账号。
- 对局进行中的账号禁止改号。操作保留简要改号记录，记录本身不会占用已释放的旧号。

## 账号切换与恢复码

仙友码是公开编号，不再单独作为登录凭据。换设备、手工切号需要“仙友码 + 账号恢复码”；本设备的快捷切号会保存私密凭据并核对原账号 ID，避免旧号回收后误登另一个账号。

现有登录会话继续有效。已有玩家可在原设备“功果簿 → 账号切换与恢复码”生成并私下保存恢复码；新注册账号在本设备自动保存恢复码。微信小游戏可在个人中心复制或生成恢复码。微信本身的登录不变。

失去原设备且没有恢复码时，管理员在玩家的“改仙友码 → 账号恢复码重置”中重置，私下交给本人。恢复码仅本次显示；服务端只保存不可逆摘要。重新生成会使旧恢复码失效，不会强制中断现有会话。请勿把恢复码放进公开邀请、聊天或截图。

## ECS 更新前配置

本版本移除内置后台口令，后台只接受服务器私有环境文件中的 `ADMIN_KEY`。部署前在 `deploy/.env.ecs` 设置自行生成的长随机口令；不要提交此文件或把口令发进聊天。若未配置，游戏正常运行，管理员入口将拒绝登录。

`deploy/compose.yaml` 已把此变量传给服务端容器。按项目现有 ECS 更新流程重新构建并启动服务即可，数据库迁移 011、012 自动创建专属房、号码预留及审计表，并补充审计备注字段。更新前按现有备份流程备份 PostgreSQL；不要删除或重建数据库卷。

本次代码提交不会自动发布 ECS。
