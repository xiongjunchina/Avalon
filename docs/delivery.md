# 分阶段开发与验收

当前目标：线下同桌、每人手机进房，面对面讨论；保留在线发身份、投票和战绩。已取消游戏内语音及 RTC 账号依赖。

## 阶段1：详细设计与线框

交付：design.md、可切换页面的静态线框。核对全部角色、人数表、两个拓展、房间开关、个人中心和删除范围。线框仅用于确认信息组织，不是可游玩的实现。

## 阶段2：基础工程与连接验证

初始化锁定依赖的 TypeScript 工作区和最小网页／服务，验证 HTTP 会话与 WebSocket 多客户端同步。不接入音视频 SDK，也不建立语音模拟适配。

实际验收矩阵：iOS 微信、Android 微信各至少一台；微信链接进入、访客会话保留、多手机状态同步、Wi-Fi与移动网络切换、切微信聊天返回、锁屏返回、断线重新连接。返回时重新拉取状态并收起身份面板。记录设备系统、微信版本、结果和限制；页面不得请求麦克风权限。

## 阶段3：身份与房间

实现数据库迁移、访客会话、资料、加入房间、成员管理、设置及 WebSocket 快照。验证人数上限、重复入座、凭证失效、随机邀请、越权设置、准备重置、多页面接管、房主断线转交及重连。不接微信认证，保持独立访客身份。

## 阶段4：标准规则闭环

先完成 game-core 的状态转换与测试，再接入 UI 与持久层；覆盖5–10人每种角色配置和任务人数，安全随机发牌及个人视野，队长两种顺序、讨论、组队投票、任务、正常刺杀、结算。

必须测试：平票否决；7–10人第四任务一失败票仍成功、两票失败；蓝方提交失败被拒；未入选者不能出牌；同用户重复命令不重复推进；并发最后两票只结算一次；全局和单任务两种流局策略；刺杀命中／未命中；重启后恢复已提交票；服务端给每种角色的快照均无越权字段。

## 阶段5：拓展规则整合

女神：初始持有人、2/3/4任务触发、历任不能再查、只返回阵营、查验后交接。提前刺杀：未完成两任务不可用、流局不计任务、跳过后未来仍可用、命中胜／未命中负。组合测试：第三次成功优先正常刺杀、第三次失败及第五次流局直接终局、女神结束后才进入提前刺杀窗口。

验证拓展阶段掉线后能恢复当前操作权限与信息视野；结束后可以同房再开，上一局秘密状态不能残留。

## 阶段6：个人中心与复盘

实现历史、收藏、角色／阵营统计、设置预设。测试中断不计胜负、重复结算不增战绩、零局胜率、实名／匿名复盘差异、任务出牌永不实名、非参与者访问拒绝、删除收藏不删除对局。

## 阶段7：部署与朋友验收

准备环境配置模板、容器、HTTPS反向代理、数据库迁移和回滚说明、备份及恢复演练；不将密钥提交仓库。技术检查与真实多人验收分开记录。

第一批以5–10人线下同桌、每人手机进房的朋友局验证：正常完整一局、第五次流局、正常刺杀、女神、提前刺杀、多人掉线重连；收集操作困惑及手机访问与同步问题。验收后才标记稳定试玩版。
