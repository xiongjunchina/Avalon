# 微信小游戏 0.3.3 本地修复与验证

## 约束与基准

继续已确认的网页同步设计，仅后台开发；不操作桌面、微信开发者工具或服务器，不上传。语音仍关闭，联网验收等待备案完成。
服务端规则基准沿用 e7a814f；网页源为合并该版本后的当前工作分支，保留此前共享展示模块提取。

## 本次修复

- 候场页从错误的对局八卦盘改为网页头像网格，显示房主、准备状态、空位邀请，匹配准备/发牌条件。踢人仅命中踢出按钮，仍需确认。
- 补齐候场宝镜/提前刺杀快捷开关、候场和开房规则入口、开房角色卡说明、个人中心管理员入口、仙友列表直接邀请和刷新。
- 个人中心手风琴左对齐、栏目圆角胶囊、长昵称防遮挡；开房模式卡分行显示，补声音/规则工具按钮。
- 手指移动时实时滚动，拖回原位不误触、取消手势不点击。
- 屏幕外内容不执行绘制；规则页原首屏发出211次文本绘制，新回归要求少于90次。每帧复用一次布局，避免重复计算。没有将此数字解释为手机帧率或性能提升百分比。
- 图片失败保留30秒冷却，不随每次重绘重试；高清法相使用包内160缩略图兜底，网络恢复后仍可载入高清。
- HTTP与管理员链路区分域名校验、TLS、超时、非JSON响应；微信原生登录错误独立提示，错误中不输出密钥或原始请求内容。
- 修正候场截图脚本：两端均使用同一个用户、房主和准备状态，不再用不一致的独立示例成员。

## 实际验证

- TypeScript 通过；小游戏112项回归通过（包含本轮故障复现后修复）。
- 网页和游戏内核65项测试通过；网页构建通过，有既存大chunk提示。
- 完整 npm test：127项，78通过，49失败；失败后端用例缺少本地 DATABASE_URL。详见 dist/regression-current.log。没有触碰生产数据库。
- 独立headless浏览器生成20种页面/状态 × 320、390、430宽度的截图，位于 dist/minigame-preview。网页390参考位于 dist/web-reference，对照位于 dist/web-parity-review。
- 已人工查看候场、开房、个人中心、身份对照。几何检查仅覆盖首页/牌局选定区域，不能据此认定所有页面逐像素一致。

## 未验证与剩余边界

尚未进行真机帧率采样；字体光栅、阴影、部分页面细节仍有视觉差异，不能把本候选包称为全部一比一完成。
没有验证真实微信登录、多人联机、重连和在线管理操作；备案/HTTPS/后端登录接口生效继续留待联网验收。
本轮不包含语音，也不会自动更新手机上已经上传的0.3.2体验版。
