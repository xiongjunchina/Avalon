# 微信小游戏客户端：构建和联调

本工程已合入 `origin/main` 的 `0ab22eb`（含 9–12 人法宝、自动亮身份及最新牌局规则）。小游戏源码位于 `apps/minigame`，构建输出位于 `dist/minigame`。服务端复用现有 PostgreSQL、房间协议和游戏规则。

## 构建

在仓库根目录执行：

```powershell
$env:WECHAT_MINIGAME_API_BASE_URL='https://avalon.ccnepower.com:8443'
npm ci
npm run typecheck
npm run build:minigame
```

微信开发者工具选择“小游戏”并导入 `dist/minigame`。工程默认 AppID 为 `wxdb4e422c14adab3f`，需要换号时可用 `WECHAT_MINIGAME_APP_ID` 覆盖。`project.config.json` 保持 `urlCheck: true`。不要将 AppSecret、管理员密钥或用户令牌写入小游戏包。

## 服务端

服务端进程需从安全的部署环境读取 `WECHAT_MINIGAME_APP_ID` 和 `WECHAT_MINIGAME_APP_SECRET`。Docker Compose 通过私有 `deploy/.env.<实例名>` 将两项传入服务端容器；`AppSecret` 只留在服务端，不能写进仓库或客户端。小游戏调用 `wx.login` 后，服务端通过微信 `jscode2session` 核验临时代码并签发自身的会话令牌。新接口部署前，生产服务无法接受小游戏登录。

本轮仅做后台代码开发，未重新验证线上健康状态，也未部署本分支的新接口。上线前应读取服务器实际代码版本，并以真实 AppID 登录验证 `/api/sessions/minigame`、`/api/minigame/socket-ticket` 及房间 WebSocket。

## 微信后台合法域名

当前构建所用入口包含端口 **8443**。微信后台需将 `https://avalon.ccnepower.com:8443` 加入 request 合法域名，将 `wss://avalon.ccnepower.com:8443` 加入 socket 合法域名。开发者工具已经以开启域名校验的设置显示前者不在当前 request 列表中。填写后以开发者工具重新编译并在真机复核；不要关闭域名校验来代替配置。

若改为标准 443 入口，先让 Nginx 与证书在 443 正常服务，再以 `WECHAT_MINIGAME_API_BASE_URL=https://avalon.ccnepower.com` 重建，微信后台同步填写无端口的 HTTPS/WSS 域名。

### 生成可导入的版本包

```powershell
npm run package:minigame -- --version=0.1.0
```

命令先运行类型检查与小游戏测试，再在 `dist/releases` 下创建独立版本目录和 Windows ZIP。导入目录内的 `project` 文件夹，工程类型选择“小游戏”，不是普通小程序。ZIP 只用于交付和备份，上传时需导入解压后的工程目录。

`release.json` 记录源码提交、是否含未提交更改、AppID、API 地址、包体字节数和每个文件的 SHA-256。版本包不复用旧目录，避免将开发者工具的私有配置或无关文件带入包内。正常开发仍可导入 `dist/minigame`。
