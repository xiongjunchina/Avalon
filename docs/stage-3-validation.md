# 第三阶段：PostgreSQL 持久化验收

日期：2026-09-30。实现范围为独立网页的访客身份和等待房间；不含发牌、投票、完整对局或战绩。

## 交付

- PostgreSQL 18.4，Avalon专用Compose服务和持久卷，仅绑定127.0.0.1:55433；没有改动其他项目数据库。
- pg驱动、版本化SQL迁移；用户、会话、房间、成员、命令回执持久化。原内存演示数据不迁移。
- 事务锁与唯一约束，成功提交后广播；重复命令查持久回执，数据库故障明确失败，不回退内存。
- 30天滑动会话与Cookie同步续期；前台定期续期和切回页面重新校验。
- 允许新成员加入开关；关闭不影响已准备成员，也不阻止原成员重连。
- 加入时间决定转交；60秒离线宽限、重启宽限、空房关闭、全员离线24小时关闭、关房30天后回执清理。
- 前端连接尝试去重、旧页面停止争抢、回执按命令编号匹配、断线重放原编号；错误提示与设置页面已更新。

## 自动化结果

最终执行 `npm test`：20组通过，0失败，约31秒。使用真实数据库的随机隔离schema，清理仅作用于本次schema。未使用内存替代或跳过数据库测试。

|类别|已验证场景|
|---|---|
|持久化|服务重建后同一用户、房间、设置、准备状态及回执保留|
|并发|两个玩家抢最后一个座位只有一个成功；同一用户并发加入不同房间只成功一次|
|权限|跨源和缺少CSRF头拒绝；非成员不能查询或连接；非房主不能改设置和接纳开关|
|接纳|关闭后拒绝新成员；原成员仍能重连，准备状态保持|
|会话|数据库与Cookie同步续期；过期凭证不能复活|
|转交|60秒前不转交；重连取消转交；无人在线保留，后续成员上线接任；按加入时间而非座位|
|重启和清理|60秒重连宽限；24小时边界；重启不延长离线期限；关房保留用户；空房立即关闭|
|回执|重复命令不重复执行；同编号不同内容拒绝；关房30天后才清理|
|故障|真实数据库触发器制造写入失败，事务回滚；WebSocket不返回成功或广播新状态；数据库连接中断返回503|
|连接|恢复同一座位、新页面接管、旧页停止自动重连；同时resume只创建一次连接；旧回执不清除新请求|

## 浏览器证据

使用Codex内置浏览器的手机宽度页面访问localhost：

1. 新访客“持久化验收”进入，创建房间，将6人改为5人。
2. 设置准备并关闭新成员加入，准备未被清除。
3. 对当前本项目后端执行正常停止并重启，确认监听进程已更换；原房间号、5人设置、访客身份、准备和接纳开关保持，页面自动恢复连接。
4. 重新开放后，由本机API加入合成同伴，浏览器实时显示第二成员；浏览器复制邀请、退出、粘贴邀请重新入座成功。合成同伴随后正常退出，其临时凭证文件已删除。
5. 再次准备、关闭加入并刷新核验；截图为 stage-3-room.png 和 stage-3-settings.png。

第二成员通过本机API模拟，未冒充第二台真机。Chrome独立浏览器连接不可用，未据此宣称双浏览器或双手机人工验收。多人同步另由真实HTTP/WebSocket集成测试覆盖。

## 操作与限制

启动流程见README。前端5173、后端3001、数据库55433只监听本机。数据库所有权锁丢失后先恢复数据库，再重启后端；不自动以另一种存储继续运行。数据卷不可删除。

房主转交与离线清理由15秒扫描触发，边界最多有一个扫描周期的延迟。30天无有效续期、清Cookie或换设备将无法恢复访客身份。迁移失败阻止启动；本阶段迁移只含初始建表，不以自动删表作为回滚。

尚未完成iPhone／Android微信真机、HTTPS与公网部署验收。未购买资源、未发布公网、未接微信认证、未增加语音或收费功能。下一阶段为独立规则引擎与标准对局。

实现依据：[node-postgres事务说明](https://node-postgres.com/features/transactions)、[PostgreSQL行锁说明](https://www.postgresql.org/docs/17/explicit-locking.html)。
