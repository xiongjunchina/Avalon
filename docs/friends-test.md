# Docker + ngrok 朋友内测

本阶段在自己的 Mac 上运行完整生产构建，通过 ngrok HTTPS 链接邀请朋友。先完成真实手机对局验收，再购买阿里云 ECS、配置已有域名。当前不购买云资源、不修改 DNS，不增加微信授权或付费功能。

## 当前入口

2026-09-30 实际启动的地址：**https://uncrushed-sled-liberty.ngrok-free.dev/**。

这是 ngrok 本次实际返回并经过 HTTPS 接口验证的入口；以 `npm run tunnel -- friends status` 的当前状态为准。它转发到 `127.0.0.1:8089`，不是原8088容器试玩实例。原开发数据库、8088房间和其他应用均独立保留。

访问路径：朋友浏览器 → ngrok HTTPS → 本机 ngrok agent → 回环8089 Caddy → 容器内 Node → 容器内 PostgreSQL。后端和数据库不映射主机端口，不开放路由器端口。ngrok 请求检查已关闭，不在本地检查界面记录角色、投票或 Cookie 请求内容。ngrok 负责公网 TLS，应用仍严格要求实际 HTTPS Origin、Secure／HttpOnly／SameSite Cookie 与同源请求标识。

ngrok 会在 X-Forwarded-For 末尾附加实际客户端地址；仅 ngrok 配置的网关保留该链，后端只信任最近一跳。普通本地／ECS网关仍覆盖转发头，不能把 ngrok 专用配置拿去直接监听公网。依据：[HTTP 端点文档](https://ngrok.com/docs/gateway/endpoints/http)。

## 邀请朋友

1. 你先打开上述 HTTPS 地址，填写昵称，点击“进入游戏大厅”，再点击“创建房间”，设置实际人数。
2. 在房间点击“复制邀请链接”，发送到朋友群。朋友各自用自己的手机和浏览器打开，填写昵称进入游戏大厅，再加入受邀房间。已有访客身份时无需重复填写昵称。
3. 人员到齐后可以关闭“允许新成员加入”；已有成员依然能重连。
4. 全员准备后房主开始发牌，等待5秒，各自查看身份并确认，再开始面对面讨论和投票。
5. 结算后检查战绩、复盘，房主返回等待区即可同房再开。

首次浏览器访问可能出现 ngrok 的 **Visit Site** 提示，确认地址是上述自己的内测入口后再进入。这是 ngrok 免费端点的首次访问页面，不是游戏账号登录；正常访问不需要输入 ngrok 密码或付费。官方说明：[免费计划访问提示](https://ngrok.com/docs/pricing-limits/free-plan-limits)。不要将 API 测试成功等同于所有朋友网络均可访问，微信内、系统浏览器、Wi-Fi 和移动网络都需实测。

全程保持同一浏览器。微信内置浏览器和 Safari／Chrome 可能是不同访客身份，不能在对局中随意切换；清除 Cookie、换设备或将来换到自己的域名，也不会自动恢复旧访客账号。迁移数据库本身不能跨域搬运浏览器 Cookie；本轮战绩作为内测记录，ECS正式入口默认重新建立访客身份。

## 每次开始和结束测试

### 首次完整实局速查

建议先玩5人标准局，关闭湖中女神和提前刺杀；如果超过5人，按实际人数设置。其他玩法保持默认，先完成一局再体验拓展。

1. **开房与邀请**：房主填写昵称进入大厅，创建房间并设置人数，再把房内“复制邀请链接”得到的链接发给朋友。朋友各用自己的手机填写昵称、加入该房间；不要各自创建房间。
2. **准备与规则**：确认名单、人数和连接正常；可先查看“玩法指南”中的规则、角色说明。全部设置完成后，各点“我已准备”。人员到齐可关闭“允许新成员加入”。
3. **发牌与身份**：房主点击开始发牌，确认所有人都经历5秒倒计时。每人私下查看角色名称、图案和身份线索，再点“我已记住身份”；不要向他人展示手机。
4. **完整对局**：依次进行队长选人 → 面对面讨论 → 全员赞成／反对 → 入选队员提交任务牌。各手机应显示相同的公共进度；蓝方三次任务成功后仍需完成刺杀，直到出现胜负结算。
5. **恢复检查**：找一个非关键操作时刻，让一位玩家刷新或短暂切到聊天再返回，确认账号、座位、身份和进度保留，随后继续完成原局。始终使用同一浏览器，不清除Cookie，不用隐私模式。
6. **结算与记录**：核对所有人的胜负一致；到个人中心查看本局战绩、角色／阵营统计和复盘。房主点击“回到等待区，再开一局”，检查同房准备流程可再次使用。

通过标准：能自然完成一局、私密信息仅本人可见、公共状态同步、刷新可恢复、结算及战绩正确。首局不要求覆盖全部分支；7人以上的女神／提前刺杀留到下一轮。

遇到问题记录：`时间｜房间码｜手机及系统／浏览器｜Wi-Fi或移动网络｜所处阶段｜刚才操作｜预期／实际结果`。保存截图时遮挡尚未公开的身份。若连接断开先在原浏览器返回或点“重新连接此页面”，不要反复换浏览器或新建账号。

### 运行与停止

命令在 `/Users/xjun/Gitrepo/Avalon` 运行。本机 ngrok 已安装并配置，本次没有改动其认证文件。

```sh
npm run deploy -- friends up
npm run tunnel -- friends start
```

已有匹配端点时直接复用；agent存在但端点已停时只恢复本应用端点。macOS上agent未运行时，`start` 将它交给用户会话的launchd独立运行，等待准确的端点就绪后退出启动命令；关闭检查命令不会停止隧道。配置与运行日志位于忽略版本管理的私密目录 `deploy/runtime/`，没有复制到系统启动目录，不随登录或开机自动启动，也不在退出后自动重启。

保持Docker和电脑运行、联网，电脑不要睡眠或合盖。退出macOS登录或重启电脑后，重新执行上述启动命令。其他操作系统保留前台运行；如需在macOS前台排查，使用 `npm run tunnel -- friends foreground`，前台模式仍依赖命令窗口。不要用前台模式承载需要跨检查会话持续运行的内测。

```sh
npm run deploy -- friends status
npm run tunnel -- friends status
```

测试结束先备份，再停止本应用的公网端点和容器：

```sh
npm run deploy:backup -- friends
npm run tunnel -- friends stop
npm run deploy -- friends stop
```

`tunnel stop` 通过仅监听本机4040的 agent API，核对名称、地址、上游和inspect设置后只停止 `avalon-friends`；不停止其他端点，不删除数据，也不注销 ngrok 账号。后台agent可继续空闲运行，但不会自行重新开放该端点。管理接口依据 [ngrok Agent API](https://ngrok.com/docs/gateway/agent/api)。下次使用前面的启动命令即可。不要执行 `down -v`。

## 重建与重复验收

已经生成权限0600的 `deploy/.env.friends`，包含随机数据库密码，禁止发到群里。首次配置入口如下；已有匹配文件不会覆盖，参数不匹配时拒绝操作。

```sh
npm run deploy:tunnel:setup -- friends https://uncrushed-sled-liberty.ngrok-free.dev 8089
npm run deploy -- friends build
npm run deploy -- friends up
```

构建时同时构建网页与后端，ngrok配置自动叠加 `deploy/compose.ngrok.yaml`。后续升级前先备份并使用新的 IMAGE_TAG，遵循[部署指南](deployment.md)的升级步骤，保留旧镜像。

```sh
npm test
npm run build
npm run deploy:friends:smoke -- friends
```

公网 smoke 使用7个新建“公网验收”访客和独立房间，通过 HTTPS/WSS 完成五人标准局与同房七人拓展局。检查5秒发牌、私密身份、三次任务、正常刺杀、湖中女神、提前刺杀、历史、统计、断线重连、接纳、幂等与跨源保护。不会重启服务或修改已有玩家房间；成功后退出自己的测试房，测试历史仍保留。失败时关闭测试连接，房间由正常24小时离线清理处理，不强删数据。报告在 `deploy/evidence/friends-smoke-*.json`，不保存 Cookie、角色或邀请。

脚本最后验证访客限流，同一公网IP可能短暂不能创建新访客（最多一个限流窗口）；应在邀请朋友前运行，勿在实测过程中重复运行。
