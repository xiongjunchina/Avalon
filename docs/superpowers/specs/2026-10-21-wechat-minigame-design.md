# 微信小游戏客户端设计

日期：2026-10-21

代码基线：`origin/main` 的 `7ccaaa1`
项目：嘻游 · 真假猴王（Avalon）

## 目标与验收边界

为现有阿里云部署增加可由微信开发者工具导入、预览和上传的**微信小游戏**客户端。小游戏端覆盖当前网页玩家端及管理员后台的实际功能，并与网页端共用房间、账号、牌局和数据；既有网页端继续可用。客户端不通过 `web-view` 加载现有站点，也不把 React DOM 构建产物当作小游戏包。

验收以最新服务器协议、开发者工具构建、关闭域名校验后的真机测试及真实多玩家牌局为准。上传开发版本不等于审核或正式发布；上线仍要在微信公众平台提审、通过并发布。任何未具备的平台权限或第三方服务配置均要明确列为阻塞，不能以隐藏按钮代替功能同步。

## 方案选择

1. **网页封装**：复用 UI 最快，但小游戏运行时没有常规 DOM/CSS，个人主体及小游戏端网页承载能力也不应作为发行假设，无法保证完整功能和审核。弃用。
2. **React 页面适配层**：可复用部分交互，但当前页面直接使用 `window`、`document`、`localStorage`、`fetch`、浏览器 WebSocket 和 WebRTC。兼容层范围接近重写，且语音、输入、滚动和触摸仍需专项处理。弃用。
3. **独立原生小游戏客户端（采用）**：以 Canvas 渲染、微信 API 处理输入/网络/存储，复用 `packages/contracts` 的类型和 `packages/game-core` 的规则；后端增加安全的微信会话接入。工作量较大，但可逐项验证功能、权限与真机行为。

## 代码结构与复用

在 `apps/minigame` 中放置小游戏源码、`game.js`、`game.json`、`project.config.json` 模板、构建配置、资源清单和使用说明。构建输出独立到忽略提交的 `dist/minigame`，该目录是开发者工具导入和上传对象。实际 AppID 从本地配置或构建参数注入，不能将 AppSecret、管理员口令或云服务密钥放入客户端包。

`packages/contracts` 是 HTTP、房间快照、游戏命令和推送消息的单一类型来源。`packages/game-core` 用于离线练习、规则展示和可共享的纯逻辑；正式联机对局仍以现有 PostgreSQL 服务端为唯一状态权威。将网页版可复用的错误文案、角色名称、声音/图片资源映射抽出为无 DOM 的共享模块，网页与小游戏都从共享模块读取，防止规则或文案漂移。

客户端分层为：微信平台适配器（登录、请求、WebSocket、存储、画布、声音、分享）、会话/房间传输层、页面状态层、Canvas 组件与交互层。对传输层保留原有“一个未确认命令、原 `commandId` 重试、快照版本单调前进”的规则；断线恢复不得重新生成投票或任务命令。

## 功能覆盖

以 `apps/web` 的当前行为建立逐项对照与验收用例：

| 范围 | 小游戏端要求 |
| --- | --- |
| 入口与账号 | 微信登录、昵称头像、仙友码、账号切换、退出、公告、访问状态、邀请/房间码加入 |
| 房间 | 创建、设置 5–12 人和全部玩法开关、座位、准备、房主控制、踢人、接纳开关、离开、重连 |
| 牌局 | 倒计时、私密身份、守护者线索、组队方向和草稿、讨论、赞成/反对/弃权、任务牌、照妖宝镜、提前/正常刺杀、中断、结算、同房再开 |
| 单人体验 | 与网页端相同的练习模式及机器人推进逻辑，不将练习结果写入正式战绩 |
| 社交 | 仙友搜索/申请/接受、房间邀请、房间聊天、私聊、消息提示及分享入口 |
| 个人中心 | 资料、统计、历史、收藏、复盘、常用设置、兑换入口及当前网页端其他已上线选项 |
| 多媒体 | 游戏音效、背景音乐、开关/音量；房间实时语音、静音、拒听与说话状态 |
| 指南 | 当前规则版本、角色与玩法说明，含最新守护者能力 |
| 管理 | 管理员口令验证、总览、系统策略、用户/房间/对局、封禁和资料重置、VIP、兑换码、公告及网页端已有管理操作 |

管理员入口可在小游戏中显式进入，但管理接口仍只由服务端验证权限。口令仅在使用时输入，敏感操作加二次确认；不预置于代码、持久化配置或分享参数。服务端负责权限判定与审计，客户端隐藏入口不构成安全控制。

## 微信身份、会话与安全

当前 `/api/sessions/wechat` 接受调用方直接传来的 OpenID，不能用于可信微信登录。改为客户端调用 `wx.login` 获取一次性 code，服务端持有 AppID/AppSecret 并向微信接口兑换 OpenID（以及可得时的 UnionID），再调用现有账号绑定逻辑。服务端不接受未经验证的客户端 OpenID 作为登录凭证。需定义账号合并/切换策略，避免微信登录意外接管或覆盖原访客账号。

小游戏的 `wx.request` 和 `wx.connectSocket` 使用独立会话机制；服务端为小游戏提供可轮换、可撤销的会话凭证或短时 WebSocket 票据。网页 Cookie 会话继续走现有同源 Origin/CSRF 检查；小游戏请求只走明确的小游戏鉴权分支，不以移除全局 Origin/CSRF 检查来求兼容。所有管理员请求仍需服务端管理员鉴权，不能复用普通玩家会话升权。

开发与发布都必须验证 HTTPS/WSS、证书链和域名白名单。当前部署域名为 `avalon.ccnepower.com`，入口使用 `8443`；小游戏后台填写合法域名时遵循微信当前表单规则，客户端地址与实际服务端端口一致。真机关闭开发工具的“跳过域名校验”选项后测试，不能把开发环境通过当作上线证明。

## 实时语音与外部依赖

网页端的 `agora-rtc-sdk-ng` 依赖浏览器 WebRTC，不能直接放进小游戏。先核实声网是否有适用于**微信小游戏**而非普通小程序的当前 SDK、权限和与现有语音房间互通能力；若不能满足，采用微信小游戏支持的实时语音方案，并在服务端增加对应的短时鉴权。若更换供应商导致网页与小游戏玩家无法同房语音，则不视作功能等价，必须完成互通方案或明确产品取舍后才可验收。

语音功能需要微信后台相应权限、麦克风隐私声明及第三方服务配置。第三方计费或新权限在启用前列出具体账号、授权和费用；凭证只存服务端。已有文字聊天、房间状态同步和对局功能不依赖语音服务可用性。

## 界面与资源

界面沿用现有西游剑侠风格和角色/场景资源，按手机竖屏与安全区设计，支持触摸、长列表、文字输入、私密身份遮挡、可读的大字体和网络状态提示。身份、投票、任务牌在分享图、通知和非本人画面中不得泄露。图片、音频和代码包按微信小游戏当前大小限制检查；必要资源按允许的分包/远程资源方案处理，远程资源域名同样进入白名单并完成证书验证。

所有有副作用的操作均有等待态和失败回执；断线时显示状态，收据不确定时只重放原命令。平台 `onShow`/`onHide` 处理会话续期、重连和音频暂停。网络失败、账号被封、房间关闭、多人抢占连接时给出与网页端一致的行为。

## 构建、部署与验收

1. 在与最新 `main` 对齐的隔离分支实施，不改写当前目录的未跟踪 `ops/`。先建立共享适配层与鉴权接口，再逐块实现玩家/管理页面。
2. 为微信登录代码兑换、会话权限、WebSocket 重连与命令幂等、各牌局阶段和管理员操作写有价值的自动化验证；运行仓库的 typecheck、相关测试及小游戏构建。
3. 对照网页端功能矩阵逐项走通开发者工具预览；再使用关闭域名校验的微信真机完成登录、建房、跨端同房、至少一局完整多玩家游戏、断线恢复、私密信息、好友/聊天、语音、战绩和管理员操作。记录机型、微信版本、AppID 环境、服务端版本及结果。
4. 需要服务端变更时先完成数据库迁移与兼容验证，再按现有自动部署机制上线，并验证 `/api/health` 和网页端回归。小游戏上传只在客户端与线上服务端协议相容、真机验收通过后执行。
5. 使用微信开发者工具的同一小游戏 AppID 上传开发版本，记录版本号和上传回执。微信公众平台审核与正式发布属于后续独立步骤，不把 CLI 上传成功称为已发布。

## 已知前置条件及风险

- 微信开发者工具已安装，但本机 CLI 服务端口当前关闭；上传时需在工具安全设置中启用并确认账号有该 AppID 的上传权限。
- 需要小游戏 AppID、服务端安全保存的 AppSecret，以及微信后台服务器域名配置；这些信息不能从现有网页站点推断。
- 实时语音能否沿用现有声网服务和跨端互通尚待 SDK/权限验证；若需新服务或权限，必须先完成配置和真机验证。
- 现有 `README.md` 的“无小程序”描述已经过时。实现时同步维护部署与用户文档，以代码和实测结果为准。
- 当前服务器与新 `main` 的实际版本可能不同；小游戏上传前须核对线上 API/规则版本并处理兼容性。

## 非目标

本设计不代替微信平台审核，不自动发布正式版，不把第三方密钥放入客户端，也不通过开发工具的跳过校验选项替代真实网络验证。
